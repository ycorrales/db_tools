# db_tools

Tooling for the SVT software PostgreSQL database (`svt_sw_db` / `svt_sw_db_test`,
hosted on the CERN DBOD instance `dbod-svt-sw-pgdb`, port 6600, schema `main`).

The repository holds four kinds of artifact:

| Directory | Contents |
| --- | --- |
| `sql_script/` | Schema source of truth plus one-off migration, insert and cleanup scripts |
| `sh/` | `psql` wrapper and a full dump/rebuild driver |
| `py/` | `psycopg2` helpers for schema and enum management |
| `config_json/` | Test-setup and test-type config bodies stored in the DB as JSON |
| `db-agent_json/` | Example request payloads for the SVT DB agent API |

## Requirements

- PostgreSQL client tools (`psql`, `pg_dump`). On macOS the scripts expect the
  versioned binaries `psql-17` / `pg_dump-17`, selected with `--local`.
- Python 3 with `psycopg2` for the `py/` scripts:

  ```bash
  pip install -r requirements.txt
  ```

- A `~/.pgpass` entry for the `admin` user so the wrappers run without prompting.
  `pgpass.bz2.enc` is a bzip2-compressed, `openssl enc` password-encrypted copy
  of that entry; decrypt it with the cipher and passphrase used to create it,
  then `chmod 600 ~/.pgpass`.

## `sh/psql.sh`

Single entry point for everything done over `psql`. Options are processed in
order, so `--db` and `--schema` must precede the action they apply to.

```bash
# open an interactive session (defaults to svt_sw_db_test)
./sh/psql.sh [--local] --open
./sh/psql.sh --local --db svt_sw_db --open

# run a statement, or a script file
./sh/psql.sh --db svt_sw_db_test --exec 'SELECT count(*) FROM main."Wafer";'
./sh/psql.sh --db svt_sw_db_test --run sql_script/SVT_DB_Tables_SourceOfTruth.sql

# database lifecycle
./sh/psql.sh --db svt_sw_db_new --createdb
./sh/psql.sh --db svt_sw_db_new --dropdb
./sh/psql.sh --db svt_sw_db --renamedb svt_sw_db_bk
./sh/psql.sh --db svt_sw_db --dumpdb      # writes <db>-schema.sql and <db>-data.sql

# identity sequences
./sh/psql.sh --db svt_sw_db_test --getLastValue Wafer
./sh/psql.sh --db svt_sw_db_test --restartSeq Wafer 1 false

# admin
./sh/psql.sh --db svt_sw_db --chpass
./sh/psql.sh --db svt_sw_db --chTZ
```

Flags:

- `--local` — target `localhost` and append `-17` to the client binary names.
- `--db NAME` — database for subsequent actions.
- `--schema NAME` — value of `search_path` (default `main`).
- `--all` — apply the action to both `svt_sw_db_test` and `svt_sw_db`.

`--renamedb` fills in `sh/Db-rename-template.sql`, which terminates other
backends on the source database before the `ALTER DATABASE ... RENAME`.

Dump artifacts (`svt_sw*.sql`) and `.pgpass` are gitignored.

## `sh/run.sh`

Rebuild driver: for each environment it dumps the database, renames it to
`<db>_bk`, drops it, recreates it, applies
`sql_script/SVT_DB_Tables_SourceOfTruth.sql`, then restores `<db>-data.sql`.

```bash
./sh/run.sh [--local]
```

This is destructive and must be run from the repository root (the SQL paths are
relative). Note the loop header iterates `${!DB_NAME[@]}` instead of
`${!DB_MAP[@]}`, so as committed it does nothing — fix or export `DB_NAME`
before relying on it.

## Schema

`sql_script/SVT_DB_Tables_SourceOfTruth.sql` is the authoritative definition:
schema `main`, 20 enum types and 29 tables. Broadly:

- **Silicon inventory** — `WaferType`, `WaferTypeMap`, `WaferTypeImage`,
  `Wafer`, `Asic`, `Chip`, `ChipBlock`, `AsicFamilyTypeBlockList`, plus
  `WaferLocation` / `ChipLocation` location history.
- **Probe hardware** — `ProbeCard`, `ProbeCardFamilyType`,
  `WaferProbeMachine`, `WaferLoadedInMachine`,
  `ProbeCardInstalledInMachine`, `WaferProbeProject`.
- **Equipment** — `EquipmentType`, `Equipment`, `EquipmentLocation`.
- **Test setups** — `SvtTestSetup`, `SvtTestSetupConfig` (holds the JSON config
  body as `text`), `SvtTestSetupDefaultConfig`, `SvtTestSetupEquipList`.
- **Test types and runs** — `SvtTestType`, `SvtTestTypeDUTTypeList`,
  `SvtTestTypeConfig`, `SvtTestTemplate`, `SvtTestList`,
  `SvtTestListToEntityName`.

Primary keys are `INTEGER GENERATED BY DEFAULT AS IDENTITY`; foreign keys are
`DEFERRABLE INITIALLY IMMEDIATE`.

## `py/`

- `svtconfigdbinteractions.py` — connection plus helpers: `createSchema`,
  `dropSchema`, `createEnumType`, `dropEnumType`, `addEnumValue`,
  `getAllEnumTypes`, `getAllEnumValues`, `createNewVersion`, `getMaxVersionId`,
  `commit`, `close`, `showPgqlVersion`.
- `createSchema.py` — create the schemas listed at the top of the file.
- `addAllEnumValues.py` — reconcile `enum_types.json` against the enums present
  in the target schemas, creating types and adding missing values.
- `enum_types.json` — enum name to allowed values.

Host comes from `SVT_DB_HOST` (default `dbod-svt-sw-pgdb.cern.ch`); everything
else is hardcoded in `db_params`, including a `"password"` field that currently
reads `REMOVED`. Set it, or switch the module to read `~/.pgpass`, before
running. Run from inside `py/` — `addAllEnumValues.py` opens
`enum_types.json` by relative path.

```bash
cd py
python createSchema.py
python addAllEnumValues.py
```

The `version` helpers query a `test.version` table that is not part of the
current source-of-truth schema.

## `config_json/`

Config bodies destined for `SvtTestSetupConfig.configBody`. `.json5` files are
the commented originals; the matching `.json` files are the strict-JSON versions
to load into the database.

- `ts_mit` — MIT test stand (boards, chips, power setup).
- `analog_monitoring_prober_mit` — analog monitoring on the MIT prober.
- `impedance_measurement_common_config`, `impedance_measurement_float_config`,
  `step_ramp_GSVDD_GDVDD_GAVDD_TXVDD_config` — test-type configs.
- `sldo_ts_brunel` — Brunel SLDO test stand topology.
- `SLDO_configs/` — 93 generated SLDO test-type configs under `DACScan`,
  `Irradiation`, `PowerUp`, `PowerUpAndOverCurrent`, `Psrr`, `RampRate`. The
  filename encodes the test, load and DAC preset, e.g.
  `RAMPRATE__cap_100nF__m1__dac31_3R6R.json`.

Load one with `psql`'s `\set`:

```sql
\set content `cat config_json/ts_mit.json`
INSERT INTO main."SvtTestSetupConfig" ("setupId", name, "configBody")
VALUES (1, 'ts_mit', :'content');
```

## `db-agent_json/`

Request payloads for the SVT DB agent API, each a `{"type": ..., "data": ...}`
object (or an array of them for batched requests). Grouped by operation:

- Create: `create_wafer`, `create_chip`, `create_many_chips`, `create_equip`,
  `create_equip-type`, `CreateSvtTestSetup`, `CreateSvtTestSetupConfig`,
  `CreateSvtTestType`, `CreateSvtTestTypeConfig`, `CreateSvtTestTemplate`.
- Read: `GetAll` (wafer types, wafers, asics with filter and pager),
  `get_equip`, `get_equip-type`, `GetAllWPProjects`, `GetAllSvtTestSetups`,
  `GetAllSvtTestSetupConfigs`, `GetAllSvtTestTypes`,
  `GetAllSvtTestTypeConfigs`, `GetAllSvtTestTemplates`,
  `GetSvtTestSetupConfigBody`, `GetSvtTestTypeConfigBody`,
  `GetEquipmentListForTestSetup`.
- Update: `UpdateSvtTestSetup`, `UpdateSvtTestType`, `change-wafer-loaded`.

Use them as templates when exercising the agent; the enum-valued fields
(`generalLocation`, `dutType`, `asicFamilyType`) must match the enums in
`SVT_DB_Tables_SourceOfTruth.sql`.

## Typical workflows

Rebuild the test database from the source of truth:

```bash
./sh/psql.sh --local --db svt_sw_db_test --dumpdb
./sh/psql.sh --local --db svt_sw_db_test --renamedb svt_sw_db_test_bk
./sh/psql.sh --local --db svt_sw_db_test --createdb
./sh/psql.sh --local --db svt_sw_db_test --run sql_script/SVT_DB_Tables_SourceOfTruth.sql
```

Update a wafer map from a file:

```bash
./sh/psql.sh --local --db svt_sw_db_test --exec \
  "UPDATE main.\"WaferTypeMap\" SET \"waferMap\" = '$(cat path/to/ER2WaferMap_v0.json)' WHERE \"waferTypeId\" = 3;"
```
